2.1 Hook لجلب البيانات
ملف جديد: apps/backoffice/src/pages/admin/catalog/useApi.ts

Copyexport function useApi<T>(fn: (signal: AbortSignal) => Promise<T>, deps: unknown[]) {
  const [state, set] = useState<{ data?: T; loading: boolean; error?: ApiError }>({ loading: true });
  const [tick, setTick] = useState(0);
  useEffect(() => {
    const ac = new AbortController();
    set(s => ({ ...s, loading: true, error: undefined }));   // خلي الداتا القديمة ظاهرة أثناء التحميل
    fn(ac.signal).then(data => set({ data, loading: false }))
      .catch(e => { if (!axios.isCancel(e)) set(s => ({ ...s, loading: false, error: normalizeError(e) })); });
    return () => ac.abort();
  }, [...deps, tick]);
  return { ...state, reload: () => setTick(t => t + 1) };
}
الـ AbortController إلزامي. من غيره، لو المستخدم كتب في البحث بسرعة، response قديم ممكن يوصل بعد الجديد ويغطي عليه.

المرحلة 8: الوسائط (Media)
8.1 الرفع
ابعت كل صورة في طلب لوحدها (files[] فيها ملف واحد). كده كل tile ليها progress و retry مستقلين، ومشكلة حد الـ 10 ملفات في الطلب بتتحل.
ابدأ بالتوازي بحد أقصى 2 أو 3 طلبات في نفس الوقت، مش كله مرة واحدة.
Validation في الفرونت قبل الرفع:
الصور: jpg أو png أو webp، أقصاها 5MB، وأبعادها أقصاها 6000×6000.
الفيديو: mp4 أو webm أو mov، أقصاه 50MB.
حالات الـ tile: queued ثم uploading (مع pct) ثم done (ومعاه serverId) أو failed (ومعاه رسالة السيرفر وزرار retry).
منتج جديد: الملفات تفضل في حالة "بانتظار الحفظ" لحد ما خطوة save تخلص ويبقى فيه productId. ده متصمم كده بالفعل.
خطوة upload في PublishFlow:
لو كل الملفات نجحت، علّمها done.
لو فيه فشل، خلي flow.done = 'upload_fail' (الحالة دي موجودة في التصميم: "المسودة اتحفظت، لكن بعض الصور فشلت")، وماتكملش للنشر.
8.2 صور الألوان (byVariant)
⚠️ فيه فرق في الموديل: الـ UI بيربط الصورة باللون، لكن الـ backend بيربطها بمتغير (variant_id). اللون الواحد ممكن يكون ليه كذا متغير (كل مقاس متغير).

المرحلة 9: المراجعة والنشر
9.1 الـ Checklist
الـ checklist في الفرونت (category وvariants وprice وimg وperm) إرشادي بس. القرار الحقيقي للسيرفر. عدّل فيه الحاجات دي:

cat: نشاط القسم وآبائه يتحسب من شجرة categoriesApi.tree() الحقيقية، باستخدام is_active لكل عنصر في الـ path.
var: متغير واحد على الأقل is_active. شيل شرط available.
price: حسب القناة: retail يبقى retail > 0، wholesale يبقى wholesale > 0، both يبقى الاتنين. السيرفر بيرفض الصفر، فالشرط > 0 مش "مش فاضي".
img: صورة واحدة على الأقل من صور المنتج العامة (media.general) حالتها done أو pending هتترفع. ⚠️ السيرفر بيفحص getMedia('images') على المنتج نفسه، فصور المتغيرات مابتتحسبش. عدّل imgCount يحسب general بس.
perm: useCan('products.publish').
9.2 خطوة النشر
Copyawait productsApi.update(id, { status: 'published' });
نجاح: status = 'published' وحدّث published_at.
422 فيه errors.status (array): اعرض القائمة في PublishFlow كحالة "المسودة اتحفظت، لكن النشر اترفض"، وكل سبب معاه زرار يودّي للتاب المناسب. (أسباب الأسعار تودّي للمتغيرات، والصور للوسائط، والقسم للأساسي.) اعرض النص العربي اللي جاي من السيرفر زي ما هو.
403: "ليس لديك صلاحية تغيير نشر المنتجات".
9.3 تعديل منتج منشور
السيرفر بيعيد الفحص مع كل update. لو التعديل كسر شرط (مثلًا شلت سعر)، هيرجع 422 بـ errors.status. اعرضها بنفس الطريقة، ونبّه في الـ UI: "المنتج منشور: أي تعديل لازم يحافظ على شروط النشر".

المرحلة 10: العربي والإنجليزي (مراجعة شاملة)
اتجاه الحقول:
