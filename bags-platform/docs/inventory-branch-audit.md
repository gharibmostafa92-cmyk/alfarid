# مراجعة تنفيذ branch.txt

تاريخ التحقق: 23 أكتوبر 2026.

تمت مراجعة التنفيذ مقابل Controllers وRequests وResources وTransferService وStocktakeService، وإصلاح النواقص التالية في الواجهة واختبارها.

| المرحلة | نتيجة المراجعة |
| --- | --- |
| 0 — حدود العمل | نفس Vortix وShadow DOM ومسارات `/dashboard#/inventory/*`. لم تُضف واجهة مستقلة. اختُبر `/production` القديم على Laravel حقيقي. |
| 1 — البنية المشتركة | Types وendpoints ومفاتيح إعادة المحاولة موجودة. أُضيف أمر typecheck للحزم ذات الصلة، وتصحيح إرسال low_stock كـ1/0، وتوثيق عقد الأخطاء الفعلي. |
| 2 — الفروع والمواقع | تحميل جميع الصفحات، CRUD والصلاحيات، استقلال صلاحية حذف الموقع عن تعديله، وإظهار أخطاء التحقق. أُضيف useBranchesWithLocations وكاش مواقع داخل السياق يُبطل عند الكتابة. |
| 3 — المتغيرات | بحث مؤجل 300ms، وعدم عرض نتائج قديمة أثناء التحميل، وإثراء كاش الأسماء دون مسحه عندما تصل استجابة تحمل SKU فقط. |
| 4 — الأرصدة | فلاتر hash، كميات السيرفر، اسم الموقع، وKPI المتاح محدد بالصفحة. زر تسوية الصف يمرر فرع الصف وموقعه حتى عند عرض جميع الفروع. |
| 5 — الحركات | مؤشرات السابق/التالي الفعلية، إعادة المؤشر عند الفلترة، ضبط نطاق التواريخ، وإظهار التكلفة كعملة حسب الصلاحية. |
| 6 — التسويات | الأنواع الخمسة، أخطاء الصفوف، كميات عربية، نقص الرصيد، وإعادة المحاولة بنفس Idempotency-Key. |
| 7 — التحويلات | إنشاء وتعديل المسودة، مراحل بكميات تحمل ID البند وexpected_version، تعارض409 وتحميل يدوي، عجز الاستلام، والإلغاء قبل الشحن فقط. المصدر مقيد بفرع الموظف؛ وجهة التحويل تظل فرعًا نشطًا مختلفًا وفق عقد TransferService. أفعال التفاصيل تراعي فرع الإرسال والاستلام. |
| 8 — الجرد | إصلاح منع الجرد الشامل فوق500 صنف؛ اختُبر501 صنف فعليًا في fixtures. حفظ dirty فقط مع مقارنة رقمية للقيم العشرية، وصفر مقابل null، وإظهار فرق السيرفر، ومنع الاعتماد قبل حفظ التغييرات، والتحذير قبل الخروج، وstale/recount، والإلغاء والحذف وفق الحالات والصلاحيات. |
| 9 — الإنتاج | منع التكرار والمتغيرات المكررة، وتقييد الفرع، وقراءة paginator الخام، وإخفاء التكلفة حسب الصلاحية. إدخال5.5 في خانة integer لا يُحوَّل خطأً إلى55. |
| 10 — التحقق | typecheck والبناء الكامل واختبارات المتصفح وLaravel الموضحة أدناه. لا توجد بيانات INV_BRANCHES/INV_PRODUCTS/INV_TRANSFERS أو setDb/demoState ضمن شاشة المخزون المتكاملة. |
| 11 — اختياري | لم يُنفَّذ: توسعات backend الاختيارية تحتاج قرارًا منفصلًا كما ينص الملف. |

## التحقق

من `frontend`:

```powershell
pnpm -r typecheck
pnpm build
node tests/inventory-integration.e2e.cjs
```

اختبار integration يغطي CRUD الفروع والمواقع وكود الموقع المكرر، مستخدم عرض فقط ومستخدم مقيد، فلاتر الأرصدة وdeep links، cursor، التسويات الخمس ونقص الرصيد وثبات المفتاح، التحويل والنسخة والعجز والإلغاء، الجرد وصفر/null وdirty وstale/recount ودفعة501 صنف والإلغاء والحذف، والإنتاج، و403/404/409 وفشل الاتصال وempty وإعادة المحاولة، وRTL والوضعين وشاشة390×844، وعدم وجود pageerror.

شُغّلت ست مجموعات Laravel على PostgreSQL معزول باسم `alfarid_inventory_audit_20261023`: **73 اختبارًا، 378 تحققًا، جميعها ناجحة**:

- BranchEndpointsTest وLocationEndpointsTest.
- InventorySystemTest وInventoryReviewFixesTest وInventoryReviewCompletionTest.
- ManufacturingBusinessTest.

التشغيل الأول على قاعدة الاختبارات العامة أظهر تعارضات migrations؛ أُعيد التحقق على قاعدة خاصة بهذه المراجعة ونجحت المجموعات معًا. لا يُعتد بنتيجة تشغيل متداخل على قاعدة عامة.

اختبار إضافي بلا ردود API مصطنعة:

```powershell
node tests/inventory-live.e2e.cjs
```

يشترط تشغيل Laravel محليًا على `INVENTORY_API_URL` (الافتراضي8011) مع قاعدة تدقيق معزولة ومهاجرة، ثم تشغيل fixture `tests/fixtures/inventory-live-setup.php` بمتغير DB_DATABASE المطابق لاسم قاعدة التدقيق. يرفض fixture أسماء قواعد البيانات الأخرى. استخدم DatabaseSeeder وحساب Super Admin وحساب storekeeper مقيدًا بالفرع. تم اختبار التسويات الخمس، رفض نقص الرصيد، عدم تكرار الإنتاج، دورة التحويل وتعارض النسخة، اعتماد جرد بصفر ورفض غير المعدود، إدخال٥٫٥ من المتصفح، `/production` القديم، وتقييد الفرع في المتصفح والـAPI الحقيقي.

التحقق الحقيقي آلي وقابل للتكرار؛ ليس ادعاءً بأن مستخدمًا بشريًا نفّذ جلسة قبول يدوي. أُوقف خادم التدقيق وحُذفت قاعدة التدقيق ورموز الوصول المؤقتة بعد نجاح الاختبار. البناء يُصدر تحذير حجم bundle فوق500KB، لكنه ينجح.

## حدود السجل

هذه مراجعة للحالة النهائية للكود الموجود مع إصلاح نواقصه، وليست إثباتًا بأن التنفيذ التاريخي جرى بترتيب المراحل أو أن كل مرحلة كان لها commit مستقل. لم تُضم التغييرات الموجودة مسبقًا أو التعديلات المتزامنة غير المتعلقة بهذه المراجعة إلى commits جديدة.
