# استكمال واجهات العمليات — 2026-10-27

## نطاق العمل والقرار التجاري

هذا المشروع للتصنيع. أكد المستخدم أن البراندات والموردين والمشتريات ليست ضمن نشاطه. لذلك تظل قاعدة `ManufacturingBusiness` الحالية كما هي، وتظل واجهات هذه الأقسام متوقفة في الخادم. أُخفيت روابطها وتقرير الموردين من تنقل العمليات، وأصبحت الروابط القديمة تعرض رسالة توقف دون تحميل بيانات هذه الوحدات. أزيل اختيار البراند من استهداف العروض. ملفات الوحدات القديمة باقية للحفاظ على العمل السابق، ولا تُستورد وحدة المشتريات داخل شاشة العمليات النشطة.

## ما اكتمل

- طبقة API للعمليات ومطابقة الأسماء والعلاقات مع Controllers وFormRequests وResources الفعلية؛ تحديث لقطة 226 مسارًا إداريًا في `operations-contracts/routes.json`.
- توحيد استجابات Laravel سواء كانت Resource collections أو paginator ببيانات pagination في المستوى الأعلى. القوائم الفارغة تحتفظ بحجم صفحة صالح.
- الطلبات: pagination وفلاتر بأسماء الخادم، تفاصيل وبنود وتاريخ تغييرات حقيقي، تغيير الحالة والدفع، تخصيص وفك المخزون، وإنشاء الشحنة من endpoint المخصص. أزيلت تفاصيل وهمية كانت تظهر عند خلو الاستجابة أو فشلها.
- المرتجعات: إنشاء من بنود طلب مسلّم، عرض السبب والملاحظات والتواريخ الفعلية، اعتماد واستلام وفحص واسترداد. إصلاح الكمية السليمة الافتراضية عند الاستلام وترجمة مفاتيح طرق الاسترداد إلى قيم الخادم. فشل الإلغاء لا يؤدي إلى محاولة حذف تلقائية.
- الشحن والتسعير ومجموعات العملاء والعروض والكوبونات: نماذج وحفظ فعلي، اختيارات بمعرّفات حقيقية، تصدير واستيراد CSV لقائمة محددة وعرض تقرير الاستيراد الفعلي. متغيرات المنتجات تأتي من مساراتها المتداخلة.
- المالية والورديات والجملة: عقود الخزائن والأرصدة والمصروفات الصحيحة، التحويلات والمراجعة، تفاصيل الوردية، تسعير عروض الجملة وإنهاؤها، مراجعة إشعارات السداد والإيصالات المحمية.
- التقارير النشطة: مبيعات ومخزون وأرباح وورديات من `rows` و`totals` وحقول `ReportService` الفعلية. الفترة مشتركة بين التقارير الزمنية. لا يرسل المتصفح تقريرًا لفترة غير صالحة أو تتجاوز 366 يومًا شاملة البداية والنهاية؛ الخادم يطبق القاعدة بالفعل. مجاميع فرق النقدية والمرتجعات محسوبة للورديات المعروضة، لأن الخادم يعيد حتى 200 وردية.
- الإشعارات: UUID، metadata وعدد غير المقروء من الخادم، تعليم المقروء مع rollback عند الفشل، قراءة غير المقروء المحمّل بالتتابع، تحميل المزيد، polling كل دقيقة عندما تكون الصفحة ظاهرة، وربط السجل الصحيح.
- البيانات التجريبية: لا شبكة مطلقًا عند `VITE_USE_MOCK_OPERATIONS=true`؛ fallback للشبكة و5xx فقط مع تنبيه. 403 و404 لا تتحول لبيانات تجريبية. الطلبات المتأخرة الملغاة لا تكتب فوق الفلتر الجديد. حفظ السجلات التجريبية ممنوع، والنقر المتكرر لا يكرر mutation.
- تحسين المكونات المشتركة: Dropzone يمرر الملف الفعلي؛ ConfirmModal ينتظر الحفظ ويحترم فشله؛ تنبيهات وإعادة محاولة للتحميل. ملفات CSS الخاصة بالتصميم لم تتغير في هذه الجلسة.

## التحقق

من `bags-platform/frontend`:

```powershell
pnpm install --frozen-lockfile --ignore-scripts
pnpm --filter @alfarid/api-client typecheck
pnpm --filter @alfarid/backoffice lint
pnpm --filter @alfarid/backoffice build
pnpm test:operations
```

اختبار المتصفح يستخدم Edge مع سياق معزول واستجابات API مضبوطة ومطابقة للعقود، ويختبر التطبيق الفعلي بما فيه Shadow DOM والمصادقة عبر handoff اختباري. لا يستخدم جلسة المستخدم ولا ينشئ عمليات مالية في قاعدة بياناته:

```powershell
pnpm --filter @alfarid/backoffice dev --host 127.0.0.1
pnpm test:operations:e2e
$env:OPERATIONS_MOBILE='true'
pnpm test:operations:e2e
Remove-Item Env:OPERATIONS_MOBILE
```

يمكن تغيير العنوان عبر `BACKOFFICE_URL`. اللقطات في `test-results/operations/` و`test-results/operations-mobile/` من جذر المستودع. الاختبار يغطي الفترة، بيانات التقارير، pagination الطلبات، تفاصيل الطلب، استلام واسترداد المرتجع، فشل قراءة إشعار والتراجع عنه، المالية والورديات والجملة، الشحن والتسعير والعروض، الروابط المتوقفة، و404 مع إعادة محاولة. اختبارات hooks تغطي منع الشبكة في mock، الرد المتأخر، 403، fallback، ومنع النقر المزدوج، إضافة إلى توقف polling عند إخفاء الصفحة ورجوع حالة القراءة عند الفشل. تحقق mutation بإزالة حارس إلغاء الرد أثبت أن اختبار الرد المتأخر يفشل ثم أعيد الحارس.
