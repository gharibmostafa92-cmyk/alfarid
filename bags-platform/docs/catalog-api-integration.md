# مراجعة تنفيذ store.txt

تمت مراجعة خطة ربط المنتجات والبراندات في 23 أكتوبر 2026. الصفحتان تستعملان API الحقيقي داخل تصميم Vortix الحالي واتجاه RTL، مع الاحتفاظ بصفحة الأقسام وتسجيل الدخول.

## عقد API الفعلي

المصدر: Controllers وRequests وResources في backend، واختبارات `tests/Feature/Admin/Catalog` التي ترسل طلبات HTTP عبر Laravel. اختبارات المتصفح تستخدم استجابات مطابقة لهذا العقد؛ لا تدّعي اختبار حساب R2 خارجي أو صلاحيات حساب إنتاج.

كل المسارات التالية تحت `/api/v1/admin` وتتطلب جلسة المستخدم وصلاحيات العملية.

| المسار | الطلب والرد |
| --- | --- |
| GET /categories?tree=1 | `{data:[...]}`؛ كل قسم يتضمن `parent_id`, `is_active`, `children` |
| GET /brands | بحث، حالة، pagination؛ `{data,links,meta}`، الترتيب من السيرفر |
| GET /brands/{id} | `{data:Brand}`، يتضمن الأوصاف واللوجو وعدد المنتجات |
| POST /brands | multipart: أسماء، أوصاف، slug، ترتيب، حالة، logo اختياري؛ `{data:Brand}` |
| POST /brands/{id} | multipart مع `_method=PUT`؛ `remove_logo=1` للإزالة |
| DELETE /brands/{id} | `{message}`؛ 422 عند الارتباط بمنتجات، بما فيها المحذوفة |
| GET /products | `{data,links,meta}`؛ كل الفلاتر في URL، والإحصاءات بطلبات مستقلة غير مفلترة |
| GET /products/{id} | `{data:Product}`؛ `dimensions` متداخلة، وcategory وbrand وvariants |
| POST /products | JSON للبيانات والمتغيرات؛ السيرفر يولّد code وSKU والباركود |
| PUT /products/{id} | JSON للبيانات فقط؛ الحالة بطلب منفصل؛ لا تُرسل variants هنا |
| DELETE /products/{id} | `{message}` |
| GET /products/{id}/variants | `{data:Variant[]}` |
| POST /products/{id}/variants | JSON، `{data:Variant}` |
| PUT /products/{id}/variants/{variantId} | الحقول المتغيرة فقط، `{data:Variant}` |
| DELETE /products/{id}/variants/{variantId} | `{message}`، مع حماية آخر متغير نشط للمنتج المنشور |
| GET /products/{id}/media | `{data:Media[]}`؛ `variant_id=null` للصور العامة والفيديو |
| POST /products/{id}/media | multipart؛ images مع `files[]` وvariant_id اختياري، أو video مع `file`؛ `{data:Media[]}` |
| PUT /products/{id}/media/reorder | `{ids:[...]}` للصور العامة المحفوظة |
| DELETE /products/{id}/media/{mediaId} | `{message}`؛ حماية آخر صورة عامة للمنتج المنشور |

`VariantResource` يرجع اللون تحت `color:{name_ar,name_en,hex}` والصور تحت `images`. `cost_price` لا يرجع بدون `products.view_cost`، ولا ترسله الواجهة بدون الصلاحية. `BusinessException` يرجع HTTP 422 افتراضياً، وشكله `{message,errors}`. رفض النشر يحتوي `errors.status` كمصفوفة نصوص؛ أخطاء المتغير الفردي تأتي بدون prefix.

## قرارات التكامل

- ترتيب `name` في API بحسب الاسم الإنجليزي؛ الواجهة تسميه «الاسم (EN)».
- صورة اللون تُربط بأول متغير محفوظ لهذا اللون بحسب ترتيب الصفوف، وتُجمع عند القراءة باسم اللون الإنجليزي. حذف المتغير يحذف صوره؛ حوار الحذف ينبه لذلك. هذا هو عقد الإدارة المعتمد هنا، ويجب أن يستهلكه المتجر بنفس المعنى.
- رفع الملفات يمر عبر backend الحالي الذي يخزنها على R2؛ الواجهة لا تحتوي مفاتيح تخزين. معاينات الملفات المحلية مؤقتة وتُلغى عند انتهاء عرضها.
- اختيار المورد يظل معطلاً كما في التصميم لأن قائمة الموردين غير مجهزة بهذه الشاشة؛ قيمة المورد المحفوظة تُحفظ عند التعديل.
- استخدمت اختبارات Laravel المعزولة بدلاً من إعادة تشغيل Seeder على قاعدة المستخدم. لم تُمسح أو تُعد تهيئة قاعدة البيانات.

## التحقق

- Laravel Catalog: **119 اختباراً، 542 assertion ناجحة**.
- اختبارات Node للمحوّلات والحفظ والتحقق: **10 ناجحة**، عبر `node --test tests/catalog-mappers.test.cjs tests/catalog-persist.test.cjs tests/catalog-validation.test.cjs` من مجلد frontend.
- اختبار Edge عبر Playwright: `node tests/catalog-api.e2e.cjs` مع توفر Playwright في NODE_PATH. يغطي الإنشاء ثم الرفع ثم رفض النشر وإعادة المحاولة والنشر، عدم تكرار المنتج والصورة، multipart البراندات ورفض حذفها، 404، العرض فقط، والموبايل.
- `pnpm --filter @alfarid/backoffice build` يجمع TypeScript ونسخة الإنتاج.
