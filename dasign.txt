ممكن تكون شاشة مستقلة باسم عملاء التجزئة، مع إعادة استخدام نفس مكونات التجار الحالية.

قائمة العملاء:
- اسم العميل.
- رقم التليفون.
- البريد الإلكتروني.
- حالة الحساب.
- زر فتح التفاصيل أو تعديل البيانات.
- بحث، وترقيم صفحات حسب استجابة الـ API.
مصدر البيانات GET /api/v1/admin/customers، مع تخصيص القائمة لعملاء التجزئة؛ متستخدمش business_only: 1 لأنه المستخدم حاليًا لعرض التجار فقط.

نموذج إضافة عميل:
الحقل	مطابقته للـ backend
الاسم	name — مطلوب
رقم التليفون	phone — مطلوب وفريد، رقم موبايل مصري
البريد الإلكتروني	email — اختياري
كلمة المرور	password — مطلوبة، 8 أحرف على الأقل
نوع العميل	type — تجزئة، يتحدد تلقائيًا في الشاشة
حالة الإنشاء	status — pending أو approved حسب الصلاحيات وقواعد الخدمة


الحفظ: POST /api/v1/admin/customers.

تفاصيل وتعديل العميل:
- تحميل البيانات: GET /api/v1/admin/customers/{id}.
- تعديل الاسم والتليفون والبريد.
- تغيير كلمة المرور اختياري؛ متبعتش الحقل لو المستخدم سابه فاضي.
- الحفظ: PUT /api/v1/admin/customers/{id}.
- نوع الحساب وحالته مش بيتعدلوا من نموذج التعديل العادي؛ الـ backend مانع إرسال type وstatus فيه.
خلي إجراءات الحالة منفصلة عن حفظ البيانات، وحسب الصلاحية. ومتضيفش مستندات شركة أو سجل تجاري في نموذج التجزئة.

- تحديث حالة الطلب وتسجيل الخروج.
