### Open findings

- Database integrity still needs a commit-time guarantee that wallet and treasury balances match their ledger chains, and a database check for aggregate wholesale allocation limits. The application already serializes coupon redemption by coupon and identity. The database does not yet enforce the full order total formula across sales channels.
- Historical migrations still include blocking DDL and concurrent indexes that need recovery and lock review. Financial foreign-key delete policies, retention, monetary precision and redundant indexes need a legacy data and query-plan review. The invoice counter is row-locked. Other sequence-backed numbering can leave gaps after rollback.
- The new migrations have to be rehearsed against a production-shaped database. Duplicate wallet references or multiple reversals need reconciliation before the corresponding unique indexes can be built. Existing invalid CHECK values and orphan coupon references must be corrected before validation can finish.
- Deploy the wallet reversal code to all workers before enabling the adjustment immutability trigger. Older workers link reversals with a separate UPDATE and cannot run against the new trigger. Assign the new POS shift permissions to the authorized staff roles before switching traffic. Rehearse the actual login's grants, TLS and proxy configuration, new and existing connection timeouts, scheduler overlap, provider callbacks, and the release gate in staging.
- Production Redis, PgBouncer, failover, backup recovery, and rollout verification remain open. Performance decisions such as dropping stock indexes or changing worker and connection limits require workload measurements.

## Local closeout

- Adding staff roles or adding permissions to a role requires the acting employee's current password. The checks run before mutation under the staff administration lock. The backoffice prompts for the password when saving an addition. Permission grants proposed through the assistant must be made from the backoffice so passwords stay out of assistant requests.
- Staff handoff codes retain the one-minute lifetime and single-use behavior. The exchange checks the issuing network identity and browser user agent. If either changes in transit, restart sign-in. Different browser sessions can share both properties.
- With three Redis Sentinels and the repository HAProxy data configuration on an isolated Docker network, writes recovered in 5.7 and 9.1 seconds across two runs after stopping the primary. The former primary rejoined as a replica and copied the write made after promotion. The HAProxy internal API path served 10/10 requests after one of three test application containers stopped.
- A custom `ALERTMANAGER_CONFIG_DIR` can contain `alertmanager.yml` and its SMTP password file outside the repository. Compose mounts this directory read-only at `/etc/alertmanager`. Prometheus evaluated a synthetic rule and Alertmanager delivered the resulting alert to an isolated SMTP sink.
- A local PostgreSQL archive containing 100 tables and 174 applied migrations restored successfully to a scratch database. The prior restore-script test also rejected a corrupted archive and removed the scratch database after each attempt.

The selected backend suites passed 288/288 tests with 1,341 assertions. Frontend type checking, the backoffice build, 247 frontend tests, and the browser test for staff role assignment and credential updates passed.

The Docker drills ran on one host with test application containers and a local SMTP sink. Multi-host VIP behavior, real SMTP delivery, and restoring production data remain environment-specific checks.
